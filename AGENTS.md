# AGENTS
- Sourcing result bulk CRM additions reuse the single-prospect path sequentially with per-item outcomes; selection spans fixed ten-row pages and presentation-only Markdown formatting leaves stored summaries unchanged.
- Producer campaign prospect display strips technical source labels through a presentation-only helper; stored descriptions and separate admin views remain unchanged.
- Campaign generation eligibility is shared between the browser and Edge Function in a React-free policy module; the existing atomic reservation enforces the limit across reloads and concurrent requests, independently of manual saves.
- Importer profile rendering uses a typed, injectable read repository; the default calls the `get_importer_profile` RPC (SECURITY DEFINER, auth.uid() required, ExportVins trial accounts excluded, field allowlist, EXECUTE for `authenticated` only). Never query the enrichment tables directly from the browser.
- Importer profile translations live in a dedicated FR/EN module merged into the common i18n namespace, keeping this feature isolated from the large shared locale files.
- SEO articles live in `seo_articles`; data/meta helpers in `src/lib/seo-articles.ts` stay React-free so a future prerender/SSR can reuse them.
- `/ressources` and `/ressources/:slug` use `ResourcesLayout` (dashboard if signed in, public otherwise); the 8 private resource routes stay behind `DashboardLayout`.
- Article sitemap is served by the `sitemap-articles` Edge Function, referenced in robots.txt; static `public/sitemap.xml` keeps fixed routes.
- Extra access rights (e.g. ExportVins CRM trial) live in `user_entitlements`, not in `app_role`; server gating via RESTRICTIVE RLS + `crm_access_level`/`is_exportvins_trial_user`, so free/paid behaviour stays untouched.
- Premium pages are wrapped by `PremiumGate` in App.tsx so trial accounts never mount the page or fetch its data.
- Campaign writes by producers are guarded by the `campaigns_guard` trigger (drafts only, sensitive/status/Brevo columns frozen, archiving allowed); submission goes through `submit_campaign` RPC so the credit is debited once (`credit_consumed_at`) in the same transaction. Admins, service_role and trusted RPCs (`app.campaign_rpc`) are exempt.
- Campaign email: Claude produces structured JSON (`email_content`) rendered by the fixed template in `_shared/campaign-email.ts`; `message_html` is the only thing sent. Generation (`generate-campaign-email`) never contacts Brevo; sending (`send-campaign`, admin) never calls Claude and never retries an uncertain Brevo outcome automatically (`check`/`confirm_send`/`release` modes). `create-campaign` stays the live path until lot C switches the admin button.
- Campaign email editor (lot B): browser edits `email_content` v2 only (Tiptap per text block, images from the `media` bucket); `save-campaign-email` validates, sanitizes and renders the HTML server-side (preview/save) — the browser never sends final HTML and `save_campaign_email` RPC is service_role only. Mirror/CTA link/unsubscribe/COMPANY_NAME prefix live in the fixed template. Rollout gated by `has_campaign_editor_access` (admin, `campaign_email_editor` entitlement, or `app_settings.campaign_email_editor_enabled`) in UI, Edge Functions and `submit_campaign`; `campaigns_guard` forbids producers writing email columns directly.
- Campaign sending (lot C): custom campaigns (v2 content + HTML) are sent only by `send-campaign` from the admin review sheet; legacy pending campaigns keep `create-campaign`, which always refuses a non-empty `message_html`. Go-live is a conditional `pending_validation → active` update so notifications fire once; rejection reasons live in `campaign_events` (`rejected`), never in `client_note`. Test sends use only `BREVO_TEST_LIST_ID`, are marked by a `test_campaign` event, end `archived`, and are skipped by sync/enrichment.
